Rapha

iOS · 2025

An iPhone app that writes each user a personal Bible devotional plan for their life, struggles and faith background, and adapts it every month. Live on the App Store.

problem

Most devotional apps give everyone the same reading. People in a hard season, like grief, anxiety or a new job, have to hunt for passages that speak to them, and many drop the habit.

what i built

  • A Claude pipeline on Supabase Edge Functions that turns a short onboarding quiz into a 4-week plan. Each day has an intro, a Scripture passage, a lesson and a prayer.
  • Plans that adapt every month: near the end of a plan, a check-in asks one personal question, and that answer, the user’s favorites and how much they read shape the next plan.
  • A job queue inside Postgres: a trigger queues the later weeks and an hourly pg_cron job writes them, with retries. A retried job never overwrites a finished day.
  • A locked-down backend: every function verifies the caller’s JWT, and row-level security covers every table. It was tested with real attack attempts.
  • A SwiftUI app with a Bible reader, a Scripture-grounded chat, streaks, Apple and Google sign-in, a subscription paywall and a home-screen verse widget.

how it works

The app never calls the model directly: every AI request goes through an Edge Function that checks who is calling. Onboarding answers become a plan outline with a theme for each week, and each day is written from that outline, the user’s profile and what they have already read, so nothing repeats. At the end of a plan, the check-in answer, favorites and reading history feed the next one.

hard problems

  • Personal from the first second. A full plan takes many model calls and serverless functions have time limits, but a new user should start reading the moment onboarding ends. The first call writes the plan outline and Day 1 together and returns; the rest of the week is written after the response is sent, and later weeks are queued in Postgres and written by an hourly job with retries. Writes ignore duplicates, so a retried job never overwrites a finished day.
  • AI cost that scales with users. Every plan is long and personal, so cost per user matters. The week’s shared context goes in one cached prompt block, so each day’s call pays full price only for that day’s details. Every call has a token cap, chat has a per-user daily limit enforced on the server, and batch jobs are capped per run.
  • Scripture that can’t be misquoted. Models paraphrase, and a devotional app can’t. The model returns only verse references; the text comes from a Bible API, verse length is checked in code with a retry when it runs long, and replies are parsed against a strict schema so refusals are caught instead of shown.
  • Streaks and subscriptions that can’t be gamed. Streaks are rebuilt on the server from the list of completed days, accepting the device’s date only within a day of the server’s, so they can’t be faked or drift across time zones. Paid status is set only by a signed webhook from the paywall provider; the app itself can’t write it.

design details

  • A custom Metal shader draws the light-ray background, and particle effects pair with haptics; both step aside when Reduce Motion is on.
  • A home-screen widget shows the daily verse, sharing data with the app through an App Group and refreshing only when the verse changes.
  • The paywall is a React app served through Superwall, so it can be redesigned and tested without an App Store release.
  • Plans follow the season and the church calendar, not just the user’s answers.

stack

Swift, SwiftUI and WidgetKit. Supabase (Postgres, Auth, Edge Functions in TypeScript, pg_cron, pg_net, Vault). Claude. Superwall.
